# Передача проекта напарнику

## 1. Что решаем

Нужно спрогнозировать `quantity` — количество продаж каждой пары
`warehouse_name × article` на следующие 9 недель. После обновления ТЗ
гранулярность недельная: одна строка соответствует одной календарной неделе
с понедельника по воскресенье.

Итоговая метрика состоит из SMAPE, WAPE, RMSE, Bias и RMSLE. Основной вес у
SMAPE — 50%. Итоговый `normalized_score` сравнивается с mean13-бейзлайном:
**чем меньше, тем лучше**, 1.0 означает уровень бейзлайна.

## 3. Как подготовлены данные

Основной скрипт: `prepare_weekly_data.py`.

- Используются даты до 26.07.2026 включительно.
- История: с 01.01.2024 по 20.07.2026, всего 134 недели.
- 11 складов, 799 товаров, 8 789 пар, 1 177 726 строк.
- Построена полная сетка `week × warehouse × article`.
- `quantity` суммируется за неделю. Для недель без продаж ставится 0.
- 63.8% недельного таргета равны нулю.
- `sales_sum` и непустой `discount_sum` возвращены из логарифма через `np.exp`
  до недельной агрегации.
- Пропуски `discount_sum` заменены нулём: по пояснению экспертов это отсутствие
  скидки. В `sales_sum` было только три пропуска, их вклад считается нулевым и
  отдельно отмечается счётчиком.
- Дубликаты остатков одной пары внутри одного дня суммируются. Остатки разных
  дней не суммируются: рассчитываются начало/конец недели, min, max, mean,
  median, изменение, число известных дней и число неположительных дней.
- Отрицательные остатки не удаляются. Их очень мало: после дневной агрегации 29.
- Недельного остатка нет в 41.3% строк, поэтому пропуск нельзя считать нулём.

Готовый датасет хранится локально в
`weekly_data/weekly_dataset.csv.gz`, сводка — в
`weekly_data/weekly_summary.json`.

## 4. Бейзлайны и CatBoost

Были сделаны простые бейзлайны: все нули, последнее/среднее значение и mean13.
Основная CatBoost-версия двухэтапная:

1. классификатор определяет, будет ли продажа;
2. регрессор оценивает количество при продаже.

Лучший устойчивый набор CatBoost называется `base_calendar_network` и даёт
средний score **0.7433** на трёх rolling-окнах.

В него входят:

- склад, товар и три уровня категории;
- горизонт 1–9 и индекс времени;
- лаги продаж 1, 2, 4 и 13 недель;
- mean4, mean13, std13 и доля ненулевых недель;
- месяц, квартал, номер недели, sin/cos недели;
- средние продажи товара по сети, рост по сети, доля склада в продажах товара
  и число активных складов.

Сетевые признаки улучшили CatBoost с 0.7458 до 0.7433. Денежные признаки,
категорийный контекст, полный блок динамики, коэффициент вариации Пирсона,
автокорреляции и простые остатки устойчивого улучшения CatBoost не дали.

Подробности: `info_about_sign.md`, `experiments/rolling/ROLLING_VALIDATION.md`.

## 5. Текущий TFT

Код: `train_tft_weekly.py` и `train_tft_final.py`.

Конфигурация:

- NeuralForecast 3.3, модель TFT;
- одна глобальная модель на 8 789 временных рядов;
- прямой прогноз сразу на 9 недель;
- 26 недель входной истории;
- hidden size 32, 4 attention heads, dropout 0.1;
- 300 шагов, learning rate 0.001, robust scaler;
- loss MAE;
- календарь известен на будущем горизонте;
- четыре сетевых признака используются как исторические;
- склад и категории передаются как 78 one-hot статических признаков;
- отдельного embedding товара пока нет.

Сырой TFT даёт score **0.9109**, потому что создаёт много небольших
положительных прогнозов на нулевых точках. После правила
`prediction < 0.75 → 0`, затем округления до целого получено:

- fold 0: 0.732497;
- fold 1: 0.746914;
- fold 2: 0.739022;
- среднее: **0.739478**.

Это текущая лучшая модель и немного лучше CatBoost 0.7433. Порог выбирался
cross-fitted: удерживаемое окно не участвовало в подборе своего правила.

Финальная модель обучена на всей истории. Прогноз на 27.07–21.09.2026:
`experiments/tft/tft_final_submission.csv`. Формат проверен, 79 101 строка.

## 6. Что получилось с остатками и другими признаками TFT

Проверены группы `stock_basic`, `stock_full`, производные остатка, денежные
признаки, тренды, разреженность и автокорреляции.

На коротком screening один fold заметно улучшил только `stock_full`. После
полного обучения по 300 шагов на трёх окнах:

| fold | базовый TFT | TFT + stock_full |
| --- | ---: | ---: |
| 0 | 0.732497 | 0.731077 |
| 1 | 0.746914 | 0.745225 |
| 2 | 0.739022 | 0.742139 |
| среднее | **0.739478** | **0.739480** |

Остатки помогли на двух свежих окнах, но ухудшили раннее. Среднее практически
не изменилось, поэтому основной моделью остаётся базовый TFT. Stock-TFT хранится
как кандидат для ансамбля. Его финальный файл:
`experiments/tft/tft_stock_final_submission.csv`.

## 7. Найденные слабые места

Диагностика сделана на 237 303 точках трёх rolling-окон.

- Факт: 572 326 единиц, прогноз: 492 185. Общий недопрогноз около 14%.
- Precision ненулевой продажи 79.9%, recall 69.6%.
- 20 264 ложных продаж и 35 122 пропущенных.
- Для редкого спроса факт ненулевой в 19.8% точек, прогноз ненулевой только в
  0.08%; recall 0.17%.
- Для прерывистого спроса recall 15.9%.
- Для регулярного спроса обратная проблема: прогноз ненулевой в 90.5% точек
  против 78.1% в факте.
- В растущих рядах сумма прогноза ниже факта на 31.6%.
- WAPE растёт с 46.7% на первой неделе до 51.9% на девятой.
- Средняя общая продажа последних 13 недель в 5.3 раза выше первых 13 недель.
  В данных есть сильный временной сдвиг.
- Два крупнейших склада дают 58% продаж; 100 крупнейших товаров — 50.5%.
- При последнем `stock <= 0` продажа всё равно встречается в 45% точек. Жёстко
  обнулять прогноз по остатку нельзя.

Простое умножение всех прогнозов на коэффициенты 0.8–1.5 проверено и не помогло.
Лучшим остался scale 1.0 с порогом 0.75. Проблема различается между сегментами,
а не сводится к одному общему занижению.

Подробности: `experiments/model_weaknesses/TFT_WEAKNESSES.md` и
`experiments/model_weaknesses/IMPROVEMENT_PLAN.md`.

## 8. Что делать дальше

Рекомендуемый порядок, чтобы каждый эксперимент отвечал на один вопрос:

1. **Добавить нативные embeddings** `article`, `warehouse_name` и категорий в
   TFT. Остальную архитектуру и MAE пока не менять. Главная проверка — помогает
   ли модели знание конкретного товара.
2. На лучшей конфигурации сравнить **MAE с Negative Binomial/Tweedie или
   quantile loss**. Таргет неотрицательный, целочисленный и разреженный, поэтому
   MAE часто тянет прогноз к нулю.
3. Сделать **гибрид CatBoost-gate + TFT quantity**. Вероятность продажи берётся
   у классификатора, количество — у TFT. Порог выбирать по out-of-fold данным
   отдельно для редких, прерывистых и регулярных рядов.
4. Добавить известные будущие признаки: число праздничных, рабочих и выходных
   дней в неделе, недели перед/после длинных праздников, начало/конец месяца.
5. Сравнить обучение на всей истории с последними 78 и 52 неделями из-за
   сильного роста уровня продаж.
6. Проверить иерархию: сначала прогноз общей продажи товара по сети, потом
   распределение по складам через недавние доли, активность и остатки.
7. Для редкого спроса сравнить Croston/SBA/TSB/ADIDA из sktime/ETNA и сделать
   routing: регулярные ряды прогнозирует TFT, прерывистые — специальная модель.
8. После этого подобрать ансамбль CatBoost, TFT и stock-TFT по сохранённым
   out-of-fold прогнозам.
9. Только затем запускать ограниченный перебор input size 13/26/52, hidden size
   32/64, learning rate и числа шагов.

Перед заменой основной модели каждый кандидат должен пройти те же три rolling-
окна; лучше расширить проверку до пяти окон.

## 9. Основные команды

```powershell
# установка зависимостей
python -m pip install -r requirements.txt

# подготовка недельного датасета
python prepare_weekly_data.py

# rolling validation TFT
python train_tft_weekly.py --restart

# подбор порога и округления по сохранённым прогнозам
python analyze_tft_postprocessing.py

# финальное обучение базового TFT
python train_tft_final.py --variant base

# финальное обучение TFT с полным блоком остатков
python train_tft_final.py --variant stock_full

# диагностика слабых мест и проверка общей калибровки
python analyze_tft_weaknesses.py
python analyze_tft_scale_calibration.py

# проверки утечек и подготовки данных
python -m unittest discover -s tests -v
```

На RTX 3060 полное обучение одного финального TFT занимало примерно минуту,
один rolling-fold — около 1–3 минут в зависимости от запуска.
